# cppcheck suppressions -- firmware hardening (TOT-61 / TOT-65)
#
# Whole-program cppcheck analysis runs in CI against the real
# `idf.py` build's compile_commands.json (see the `whole-program-cppcheck`
# job in .github/workflows/firmware-ci.yml). The filtered database
# (build/compile_commands_project.json, project sources only) provides the
# cross-TU linkage that per-TU / directory-mode analysis lacks.
#
# The CI command applies the unusedFunction suppression directly via
# --suppress=unusedFunction (in scripts/run_whole_program_cppcheck.sh)
# rather than --suppressions-list, for compatibility with the cppcheck
# version in the ESP-IDF Docker image. This file documents the rationale
# and is used by the local/directory-mode analysis commands.

# unusedFunction: cppcheck's own documentation states this check produces
# false positives unless the whole program is analyzed. Even with the full
# idf.py compile_commands.json, the following remain invisible to cppcheck's
# call-graph:
#  - ESP-IDF entry points (app_main) invoked by the ESP-IDF startup code,
#  - FreeRTOS task entry points (*_task) invoked by the RTOS scheduler via
#    xTaskCreate (function-pointer registration cppcheck cannot trace),
#  - BLE/host-stack callbacks registered via function pointer.
# None are genuinely dead. Retained until cppcheck can trace RTOS/ESP-IDF
# indirect calls (tracked as a long-term tooling follow-up).
unusedFunction
