# cppcheck strict-mode suppressions — TOT-58 firmware hardening
#
# These suppressions are scoped to checks that fundamentally require
# whole-program / linker-level analysis, which is unavailable when analyzing
# ESP-IDF component firmware without a full `idf.py` build (no ESP-IDF headers
# in this environment, no compile_commands.json with cross-TU linkage).
#
# Every suppressed finding was reviewed individually (see TOT-58 audit report).

# unusedFunction: cppcheck's own documentation states this check produces
# false positives unless the whole program is analyzed. All findings here are:
#  - public component API declared in components/*/include/*.h and called
#    cross-translation-unit (cppcheck's per-TU analysis cannot see the caller),
#  - ESP-IDF entry points (app_main) or FreeRTOS task entry points (*_task)
#    invoked by the RTOS scheduler via xTaskCreate, never referenced directly,
#  - callbacks registered with the BLE/host stack via function pointer.
# None are genuinely dead. This matches the existing firmware-ci suppression.
unusedFunction

# staticFunction: every finding is a function declared in a component header
# (public include/*.h or internal *_internal.h). Making the definition static
# would conflict with its non-static header declaration (a constraint
# violation) and break the component API contract. To distinguish the few
# genuinely TU-local functions that could be made static + removed from their
# header, a whole-program build (compile_commands.json) is required — tracked
# as a follow-up once a full idf.py build is available in CI.
staticFunction
